# ASA-RV3D Method

ASA-RV3D stands for Architecture-Semantic-Aware RISC-V 3D Partitioning.

It is a research prototype for architecture-guided 2-tier partitioning of RISC-V gate-level netlists. The method does not attempt to replace a full 3D physical design flow. Instead, it focuses on early-stage tier assignment using lightweight netlist features, RISC-V architecture semantics, and balance-aware local refinement.

## Problem Setting

Given a gate-level netlist produced by ORFS/OpenROAD, the goal is to assign each instance to one of two tiers:

```text
tier0 or tier1
```

The assignment should reduce inter-tier crossing connections, maintain usable tier balance, and preserve interpretable RISC-V functional structure where possible.

The current implementation uses `crossing_connections_proxy` as a lightweight approximation of inter-tier communication. It is not a true TSV count.

## Motivation

Generic graph or hypergraph partitioning treats gate-level instances mostly as anonymous nodes. For processor designs, however, many gate-level names and structures still reflect architecture-level functions:

- control logic
- datapath logic
- pipeline state
- register-related logic
- clock/reset structures
- fetch and execute logic

ASA-RV3D uses these architecture-related traces as soft guidance for tier partitioning.

## Method Overview

ASA-RV3D has four stages:

```text
1. Gate-level feature extraction
2. Architecture semantic recovery
3. Architecture-guided initial tiering
4. Balance-repair local refinement
```

## Stage 1: Gate-Level Feature Extraction

The extractor reads the final gate-level Verilog generated by ORFS/OpenROAD and produces compact summaries:

- instance features
- cell type categories
- net connectivity summaries
- module summaries
- manifest metadata

The repository stores compact CSV/JSON outputs, but does not store large physical design artifacts such as ODB, DEF, GDS, SPEF, or full ORFS logs.

## Stage 2: Architecture Semantic Recovery

The architecture classifier assigns each instance to a lightweight semantic class.

Examples include:

```text
generated_control
generated_datapath
register_file
pipeline_state
clock_reset
csr
fetch
load_store
execute_alu
```

The classifier is rule-based and explainable. This is intentional: the current goal is to build a transparent research prototype rather than an opaque model.

## Stage 3: Architecture-Guided Initial Tiering

The first architecture-aware assignment uses semantic class preferences to build an initial two-tier partition.

This initial assignment is useful because it introduces RISC-V structure into the partitioning process. However, it can be imbalanced. For example, on `riscv32i`, the architecture-aware v1 assignment reduces crossing proxy but has poor instance and weight balance.

Therefore, ASA-RV3D treats this assignment as a starting point, not as the final solution.

## Stage 4: Balance-Repair Local Refinement

The final stage performs FM-style greedy local refinement.

Each candidate move transfers one instance from its current tier to the other tier. The move is evaluated using a score that combines:

```text
crossing proxy change
+ instance balance penalty change
+ proxy-weight balance penalty change
+ architecture placement penalty change
```

A move is accepted when it improves the objective and either keeps the assignment within the required balance region, or monotonically repairs balance when the current assignment is still outside the required region.

This monotonic balance-repair rule is important. It allows the algorithm to start from a semantically meaningful but imbalanced architecture-aware assignment and gradually move toward a feasible balanced assignment.

## Objective

The implemented objective is:

```text
objective =
  crossing_weight * crossing_connections_proxy
  + instance_balance_weight * abs(tier0_instances - tier1_instances)
  + weight_balance_weight * abs(tier0_weight - tier1_weight)
  + architecture_penalty
```

The architecture penalty is a soft constraint. It discourages unnecessary movement away from the architecture-guided tier preference, but it does not completely forbid such movement.

This design is important because hard architecture partitioning can be too rigid after logic synthesis.

## Pseudocode

```text
Input:
  gate-level netlist
  net connectivity
  architecture class for each instance
  balance thresholds

Output:
  tier assignment

1. Extract gate-level instance and net features.
2. Classify each instance into an architecture semantic class.
3. Generate architecture-aware initial tier assignment.
4. Build net-to-tier connectivity map.
5. Repeat for a fixed number of passes:
     for each candidate instance:
         old_tier = current tier
         new_tier = opposite tier
         estimate crossing gain
         estimate balance change
         estimate architecture penalty change

         if move improves objective:
             if balance constraints are satisfied after move:
                 accept move
             else if current state is infeasible and move monotonically repairs balance:
                 accept move

     stop when no profitable moves remain.
6. Report crossing proxy, balance ratios, and class-tier distribution.
```

## Relationship to FM-Style Refinement

ASA-RV3D is inspired by FM-style local partition refinement because it improves a partition through instance-level moves and gain evaluation.

It is not a full implementation of the original Fiduccia-Mattheyses algorithm. In particular, the current prototype does not implement the complete bucket gain structure, lock/unlock policy, and rollback scheme from classical FM.

A more precise description is:

> ASA-RV3D uses an FM-style greedy local refinement strategy with architecture-semantic penalties and monotonic balance repair.

## What Is New in This Project

The core novelty is not the existence of graph partitioning or local refinement. Those are established ideas.

The project contribution is the RISC-V-specific integration:

1. Recovering architecture-related semantic classes from gate-level ORFS outputs.
2. Using architecture semantics as soft tiering guidance rather than as rigid module partitioning.
3. Adding monotonic balance-repair refinement so an imbalanced but semantically useful initial assignment can become feasible.
4. Providing a reproducible public pipeline from ORFS baseline to feature extraction, architecture classification, partitioning, ablation, and visualization.

## Current Evidence

On two RISC-V benchmarks, ASA-RV3D reduces crossing proxy compared with generic balanced partitioning:

| Design | Generic Crossing | ASA-RV3D Crossing | Reduction |
| --- | ---: | ---: | ---: |
| Ibex | 18943 | 8585 | 54.7% |
| riscv32i | 6422 | 1791 | 72.1% |

Compared with connectivity-only refinement, full ASA-RV3D also shows lower crossing proxy:

| Design | Connectivity-only | ASA-RV3D | Extra Reduction |
| --- | ---: | ---: | ---: |
| Ibex | 13842 | 8585 | 38.0% |
| riscv32i | 2766 | 1791 | 35.2% |

## Limitations

- The crossing metric is a proxy, not a true TSV count.
- The method does not perform full 3D placement and routing.
- Architecture classification is rule-based.
- More RISC-V benchmarks are needed for stronger generalization evidence.
- The current refinement algorithm is a prototype and can be improved with stronger graph/hypergraph optimization techniques.

## Next Improvements

Potential algorithm improvements include:

- connectivity-only and architecture-aware comparisons across more benchmarks
- hierarchy-aware semantic classification
- physically aware crossing locality metrics
- stronger refinement with rollback or gain buckets
- parameter sweep on both Ibex and riscv32i
- integration with floorplanning or early placement information
