# Phase 2 Feature Extraction

This phase converts the clean ORFS Ibex baseline into compact project-owned CSV files.

The raw ORFS design outputs remain outside this repository:

- `~/openroad-flow-scripts/flow/results/sky130hd/ibex/base/6_final.v`
- `~/openroad-flow-scripts/flow/results/sky130hd/ibex/base/6_final.def`
- `~/openroad-flow-scripts/flow/results/sky130hd/ibex/base/6_final.odb`
- `~/openroad-flow-scripts/flow/results/sky130hd/ibex/base/6_final.gds`
- `~/openroad-flow-scripts/flow/reports/sky130hd/ibex/base/`
- `~/openroad-flow-scripts/flow/logs/sky130hd/ibex/base/`

Only lightweight summaries generated by our own scripts should be tracked.

## Run

On the cloud server:

```bash
cd ~/RV3D_Public
python3 scripts/extract_orfs_baseline.py \
  --orfs-flow-dir ~/openroad-flow-scripts/flow \
  --project-root ~/RV3D_Public
```

Expected outputs:

```text
results/ibex_features/
├── cell_type_summary.csv
├── instance_features.csv
├── manifest.json
├── module_summary.csv
└── net_summary.csv
```

## Current Feature Set

The extractor currently records:

- standard-cell instance name and cell type
- coarse cell category: sequential, combinational, buffer, inverter, clock buffer, fill/decap, antenna, tap
- simple architecture-aware class inferred from public Ibex-style instance names
- per-instance connected net names from the final gate-level Verilog
- per-module instance and cell-category summaries
- per-cell-type counts
- per-net connection counts
- selected clean-baseline report values from `6_finish.rpt`, `5_route_drc.rpt`, and `6_report.log`

This is intentionally a first-pass extractor. It gives the partitioning code a stable public-data input without claiming that the architecture classification is final.
