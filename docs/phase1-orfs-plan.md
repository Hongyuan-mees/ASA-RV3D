# Phase 1 ORFS Baseline Plan

Date: 2026-09-14

This note defines the conservative Phase 1 plan before downloading or installing OpenROAD-flow-scripts.

The goal of Phase 1 is only to run a public Ibex + sky130hd baseline flow and record reproducible outputs. It is not a 3D IC flow yet.

## Public Sources

Primary flow repository:

- Name: OpenROAD-flow-scripts
- Upstream: https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts
- Documentation: https://openroad-flow-scripts.readthedocs.io/
- Build/run scripts license: BSD 3-Clause

Important license note:

- The ORFS build and run scripts have their own BSD 3-Clause license.
- Tools, platforms, and designs inside the flow can have separate licenses.
- Record the exact commit ID after cloning.

Processor design:

- Name: Ibex
- Upstream: https://github.com/lowRISC/ibex
- License: Apache License 2.0 unless otherwise noted by upstream
- ORFS includes an Ibex SystemVerilog design snapshot under `flow/designs/src/ibex_sv/`.

Initial platform:

- Name: sky130hd
- Reason: public/open platform supported by ORFS
- ORFS design config path: `flow/designs/sky130hd/ibex/config.mk`

## Why Use The ORFS Ibex Example First

The first baseline should use the official ORFS Ibex example instead of integrating Ibex manually.

Reasons:

- it reduces setup risk for a beginner-friendly first run
- it uses a public RISC-V processor rather than an unrelated benchmark
- it gives us a known RTL-to-GDS baseline before adding any partitioning logic
- it helps identify which files and reports are actually generated by the public flow

## Recommended Server Layout

Keep large third-party tools and generated outputs outside this project repository.

```text
approved-user-workspace/
├── RV3D_Public/           # this project repository
├── openroad-flow-scripts/ # public ORFS checkout, outside this repo
├── rv3d_runs/             # project-owned generated run outputs
└── rv3d_cache/            # optional project-owned cache area
```

Do not place ORFS inside `RV3D_Public/third_party/` during the first baseline setup.

## First Download Step

The first download step should only clone ORFS and record its commit.

Do not build OpenROAD from source yet.
Do not run the Ibex flow yet.
Do not run any global Docker cleanup command.

Planned command shape:

```bash
cd approved-user-workspace
git clone --recursive https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts.git openroad-flow-scripts
cd openroad-flow-scripts
git rev-parse HEAD
```

If the recursive clone is too large or slow, stop and report the error before trying alternatives.

## First Inspection Step

After cloning, inspect only metadata and paths:

```bash
cd approved-user-workspace/openroad-flow-scripts
ls
ls flow/designs/sky130hd/ibex
sed -n '1,120p' flow/designs/sky130hd/ibex/config.mk
sed -n '1,120p' flow/designs/src/ibex_sv/README.md
```

Expected facts to confirm:

- design nickname is `ibex`
- top module is `ibex_core`
- platform is `sky130hd`
- ORFS uses SystemVerilog files from `flow/designs/src/ibex_sv/`
- the Ibex design snapshot source and commit are documented

## First Run Strategy

The first actual run should prefer the official Docker-based ORFS path because Docker is available on the server and avoids many host dependency issues.

Before running:

- confirm available disk space again
- confirm ORFS checkout size
- confirm Docker image strategy from ORFS docs
- limit CPU threads where the selected command supports it
- run only the official Ibex baseline first

The planned first baseline target is:

```bash
cd approved-user-workspace/openroad-flow-scripts/flow
util/docker_shell make DESIGN_CONFIG=./designs/sky130hd/ibex/config.mk
```

Do not run this command until the clone and inspection steps are complete.

## Outputs To Preserve

For the first successful baseline, preserve only small summaries in Git:

- ORFS commit ID
- Docker image name/tag or build information
- Ibex config path
- selected final metrics
- final timing summary if available
- final area summary if available
- runtime
- notes about generated output locations

Large generated files must stay outside Git tracking.

## Stop Conditions

Stop and ask before continuing if any of these happens:

- clone size is unexpectedly large
- recursive submodule checkout fails
- Docker tries to perform broad/global cleanup
- generated files appear inside `RV3D_Public`
- the flow needs to write outside the approved user workspace
- the official Ibex config is missing or materially different from expected
